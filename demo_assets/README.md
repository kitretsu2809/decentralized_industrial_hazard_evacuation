# Demonstration video assets

## `pscs_i_crowd_demo_12s.mp4`

This 12-second, 1280x720 clip is an excerpt from the official PSCS-I dataset
demonstration video published by the Multimodal Data Fusion and Analytics
Group. It is included only to demonstrate predictive analysis in the simulator:
YOLO person detection, crowd-density estimation, node-level hazard-vector
fusion, and routing input generation.

- Source: https://m4d.iti.gr/wp-content/uploads/2025/12/crowd_demo_v2.mp4
- Dataset page: https://m4d.iti.gr/pscs-i-dataset/
- Dataset: *Photorealistic Synthetic Crowds Simulation in Indoor environments
  (PSCS-I)*, Pasios et al., IEEE Access, 2025,
  https://doi.org/10.1109/ACCESS.2025.3636727
- Content: synthetic Unreal Engine 5 footage; no real people are depicted.
- Permitted project use: predictive processing of the original content, such
  as object detection and generation of classification/density tags. Review the
  dataset page and FAB EULA before redistribution or any different use.

The source demonstration is not used to train a generative model. The local
excerpt was resized and encoded as H.264 with its audio removed so it stays
well below the simulator's 250 MB upload limit.

The video is kept local and ignored by Git to avoid redistributing a third-party
dataset asset. Re-create it from the authors' public demonstration with:

```bash
curl -L --fail \
  --output /tmp/pscs-i-crowd-demo-source.mp4 \
  https://m4d.iti.gr/wp-content/uploads/2025/12/crowd_demo_v2.mp4
ffmpeg -y -i /tmp/pscs-i-crowd-demo-source.mp4 \
  -t 12 -vf "scale=1280:-2:flags=lanczos" -an \
  -c:v libx264 -preset medium -crf 23 -movflags +faststart \
  demo_assets/pscs_i_crowd_demo_12s.mp4
```

## Local YOLO prerequisite

Model weights are intentionally ignored by Git. Before demonstrating on a new
clone, download the official COCO-pretrained YOLO11n checkpoint:

```bash
mkdir -p data/models
curl -L --fail \
  --output data/models/yolo11n.pt \
  https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11n.pt
```

Then copy `.env.example` to `.env`, or add this setting to the existing `.env`:

```dotenv
YOLO_MODEL_PATH=data/models/yolo11n.pt
YOLO_DEVICE=cpu
ENABLE_HSV_FIRE_FALLBACK=false
```

The standard COCO checkpoint detects people. Fire and smoke require custom
weights. The colour-only HSV fallback is disabled by default because red
equipment and video overlays can cause false alarms; enable it only for a
clearly labelled heuristic demonstration.

## Deterministic presentation clips

When the learned policy is still being trained, use the repository's scripted
scenes for a repeatable presentation. They demonstrate the operational
novelties without claiming that a checkpoint produced the decisions:

```bash
conda run -n AEDES python scripts/generate_presentation_demos.py \
  --scenario all --output-dir assets/presentation_demos
```

The output contains four 1280x720 MP4 clips:

1. `01_congestion_build_up.mp4`: density rises at a bottleneck and upstream release is throttled.
2. `02_stampede_prevention.mp4`: signs split an imbalanced crowd between two muster routes.
3. `03_hazard_rerouting.mp4`: a reactor fire isolates a route and broadcasts a detour through neighbouring nodes.
4. `04_feed_to_hazard_vector.mp4`: a clearly labelled UI-style preview of video detections, crowd density, sensor fusion, and the 32-bit packet.

The fourth clip is a presentation overlay, not a YOLO measurement. For the
real feed demonstration, start the simulator, open **Node-mapped perception**,
select a camera node, choose `demo_assets/pscs_i_crowd_demo_12s.mp4`, and click
**Assign feed and analyse**. The panel then displays detections from the
configured YOLO checkpoint (or the disclosed fallback status), the fused
hazard vector, and the packet generated by the running simulator.

## Recording the real simulator UI

The repository also includes `scripts/record_simulator_ui.py`. With the
simulator running on `127.0.0.1:8080`, it drives the real page, injects a fire
at Reactor 2, starts the simulation, switches to **Perception & Packets**,
assigns the PSCS-I feed, and records the resulting browser frames:

Record each narrative separately, with as much duration as you want before
editing:

```bash
conda run -n AEDES python scripts/record_simulator_ui.py \
  --scenario all --output-dir assets/simulator_ui_demos \
  --seconds 60 --fps 8
```

This produces five real-UI videos: `hazard.mp4`, `congestion.mp4`,
`perception.mp4`, `layouts.mp4`, and `tour.mp4`. The tour clip advances through
the existing **Guided demo** overlay, including its real incident injection
and routing-mode transitions. You can also record one scene only with
`--scenario hazard|congestion|perception|layouts|tour` and `--output`. The clips
contain the actual map, alarm state, uploaded feed, detections, density, hazard
vector, and 32-bit packet from the running application.
